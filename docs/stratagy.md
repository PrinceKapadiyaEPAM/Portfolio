# Stock Trading Strategy & Transaction Management

## 1. Overview

This system is designed to manage **stock-only trading strategies and transactions**.

The system does **not** support:

* Options
* Futures
* Commodities
* Crypto
* Forex
* Other derivatives

The primary purpose is to define a stock trading strategy, create an accumulation plan using a buy range, manage multiple profit targets, define stop-loss rules, and track the actual transactions generated by the strategy.

---

## 2. Core Trading Concept

A strategy consists of:

1. Stock
2. Buy Range
3. Accumulation levels
4. Quantity allocation
5. Multiple profit targets
6. Stop-loss configuration
7. Actual buy/sell transactions
8. Trade/position status

### Example

For a stock such as RELIANCE:

```text
Buy Range High: ₹1,500
Buy Range Low:  ₹1,400

Accumulation happens progressively as price moves
from the higher range toward the lower range.
```

Example accumulation:

| Level |  Price | Quantity | Status  |
| ----- | -----: | -------: | ------- |
| A1    | ₹1,500 |      100 | Bought  |
| A2    | ₹1,475 |      100 | Bought  |
| A3    | ₹1,450 |      100 | Pending |
| A4    | ₹1,425 |      100 | Pending |
| A5    | ₹1,400 |      100 | Pending |

The resulting position has an **average accumulated cost** based on the quantities actually purchased.

# 3. Domain Model

The system should distinguish between three concepts.

## 3.1 Strategy

A reusable set of trading rules.

Example:

```text
Strategy: Long Term Accumulation
Instrument: Stock
Buy Range: ₹1,400 - ₹1,500
SL Type: CLBS
Targets: T1, T2, T3
```

## 3.2 Trade Setup

A specific application of a strategy to a stock.

Example:

```text
Trade ID: TRD-20260819-001
Stock: RELIANCE
Strategy: Long Term Accumulation
Buy Range: ₹1,400 - ₹1,500
```

## 3.3 Transaction

An actual stock purchase or sale.

Example:

```text
Transaction:
BUY
RELIANCE
100 shares
₹1,475
```

The relationship is:

```text
Strategy
   │
   ├── Trade Setup
   │       │
   │       ├── Accumulation Orders
   │       ├── Target Orders
   │       └── Stop Loss
   │
   └── Transactions
```

# 7. Buy Range

The Buy Range represents the **accumulation zone**.

Two mandatory values are required:

* Buy Range High
* Buy Range Low

Example:

```text
Buy Range High: ₹1,500
Buy Range Low:  ₹1,400
```

Validation:

```text
Buy Range High > Buy Range Low
```

The system should reject:

```text
High = ₹1,400
Low  = ₹1,500
```

because the high must be greater than the low.

---

# 8. Accumulation Plan

The Buy Range can be divided into multiple accumulation levels.

Example:

```text
Buy Range:
₹1,500 → ₹1,400
```

Accumulation levels:

| Level |  Price | Quantity |
| ----- | -----: | -------: |
| A1    | ₹1,500 |      100 |
| A2    | ₹1,475 |      100 |
| A3    | ₹1,450 |      100 |
| A4    | ₹1,425 |      100 |
| A5    | ₹1,400 |      100 |

Each accumulation level should have:

* Level number
* Trigger price
* Quantity
* Status
* Actual execution price
* Execution timestamp
* Linked transaction

Possible status:

* Pending
* Triggered
* Partially Filled
* Filled
* Cancelled
* Skipped

---

# 9. Accumulation Quantity

The system should support quantity allocation for each accumulation level.

Example:

```text
Total Planned Quantity: 500

A1: 100
A2: 100
A3: 100
A4: 100
A5: 100
```

The system should calculate:

```text
Planned Quantity
Purchased Quantity

```

Example:

```text
Planned:    500
Purchased:  300
Remaining:  200
```

# 10. Average Cost

The system must calculate the average cost of the accumulated stock.

Example:

```text
100 shares @ ₹1,500
100 shares @ ₹1,475
100 shares @ ₹1,450
```

Average cost:

```text
(100 × 1500 + 100 × 1475 + 100 × 1450)
÷ 300

= ₹1,475
```

The Trade Setup screen should display:

```text
Purchased Quantity: 300
Average Cost: ₹1,475
Remaining Planned: 200
```

| T3     | ₹1,650 |          25% | Pending |
| T4     | ₹1,700 |          25% | Pending |

Each target should support:

* Target number
* Target price
* Quantity or percentage
* Status

* Execution timestamp
* Linked transaction

Target status:

* Pending
* Triggered
* Partially Filled
* Filled
* Cancelled
* Skipped

# 12. Stop Loss

The strategy supports different stop-loss modes.

Supported modes:

* CLBS
* WLBS

The exact calculation/trigger rules for CLBS and WLBS need to be defined separately.

The system should store:

```text
SL Type
SL Reference
SL Value
SL Status
```

Example:

```text
SL Type: CLBS
SL Value: ₹1,350
```

or:

```text
SL Type: WLBS
```

If CLBS/WLBS are dynamic rules rather than fixed prices, the system should store the rule configuration rather than only storing a final SL price.

# 13. Trade Lifecycle

A Trade Setup should have a clear lifecycle.

```text
DRAFT
   ↓
ACTIVE
   ↓
ACCUMULATING
   ↓
ACCUMULATED
   ↓
TARGETING
   ↓
PARTIALLY EXITED
   ↓
CLOSED
```

A stop-loss event can transition the trade to:

```text
ACCUMULATING
      ↓
STOP LOSS
      ↓
CLOSED
```

Possible overall statuses:

* Draft
* Active
* Accumulating
* Partially Accumulated
* Fully Accumulated
* Targeting
* Partially Exited
* Closed
* Stopped Out
* Cancelled

# 14. Transaction Management

Transactions represent actual stock executions.

A transaction should contain:

| Field              | Description                         |
| ------------------ | ----------------------------------- |
| Transaction ID     | Unique transaction identifier       |
| Trade ID           | Parent trade                        |
| Stock              | Stock symbol                        |
| Side               | BUY / SELL                          |
| Quantity           | Executed quantity                   |
| Price              | Execution price                     |
| Date/Time          | Execution time                      |
| Transaction Type   | Accumulation / Target / SL / Manual |
| Accumulation Level | A1/A2/etc.                          |
| Target             | T1/T2/etc.                          |
| SL Type            | CLBS/WLBS                           |
| Charges            | Applicable transaction charges      |
| P&L                | Realized P&L                        |

# 18. Important Design Principle

The system must not mix planned trading rules with actual executions.

### Planned

```text
Buy Range
Accumulation Levels
Targets
Stop Loss
```

### Actual

```text
Orders
Executions
Quantities
Execution Prices
Fees
Realized P&L
```

This distinction is critical.

For example:

```text
Strategy says:

A2 = BUY 100 @ ₹1,475
```

But the actual transaction could be:

```text
BUY 60 @ ₹1,476
BUY 40 @ ₹1,474
```

The system should still associate both transactions with:

```text
Trade ID
Accumulation Level A2
```

# 21. Open Requirements / Decisions

The following rules need to be finalized before implementation.

## Accumulation

* How are accumulation levels calculated?
* Are levels manually entered or automatically generated?
* Can quantities differ between levels?
* Can a level be skipped?
* What happens if price moves through multiple levels quickly?
* Should the system generate orders automatically or only generate signals?

## Targets

* Are targets entered as fixed prices?
* Can targets be percentage based?
* Is target quantity defined as shares or percentage?
* What happens to remaining quantity after T1/T2?
* Can targets be modified after accumulation begins?

## CLBS

Define:

* What does CLBS mean?
* What price/candle is used as reference?
* When is the SL considered triggered?
* Is confirmation required?
* Is there a buffer?

## WLBS

Define:

* What does WLBS mean?
* Which candle/reference is used?
* Is the wick high/low used?
* Is a buffer applied?
* When is the SL considered triggered?

## Transactions

Define:

* Manual transaction entry
* Broker/API transaction import
* Automatic order execution
* Partial fills
* Transaction charges
* Taxes/fees
* Reconciliation

# 23. Example End-to-End Scenario

```text
Stock:
RELIANCE

Buy Range:
₹1,500 → ₹1,400

Quantity:
500 shares

Accumulation:
A1: ₹1,500 × 100
A2: ₹1,475 × 100
A3: ₹1,450 × 100
A4: ₹1,425 × 100
A5: ₹1,400 × 100

Targets:
T1: ₹1,550 → 25%
T2: ₹1,600 → 25%
T3: ₹1,650 → 25%
T4: ₹1,700 → 25%

Stop Loss:
CLBS
```

If the stock reaches ₹1,500:

```text
A1 triggered
↓
BUY transaction created/executed
↓
Trade quantity = 100
```

If it falls to ₹1,475:

```text
A2 triggered
↓
BUY transaction created/executed
↓
Average cost recalculated
```

If it later reaches T1:

```text
T1 triggered
↓
SELL transaction created/executed
↓
Realized P&L calculated
↓
Remaining position updated
```

The system therefore maintains a complete history of:

```text
Strategy
   ↓
Trade Setup
   ↓
Accumulation
   ↓
Position
   ↓
Targets / SL
   ↓
Transactions
   ↓
P&L
```
